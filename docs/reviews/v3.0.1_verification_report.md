## Not a bug

**2.1: median-filled gaps in "MI before".** The fill is the documented rule at the top of `scoring.py`: a number is
scored the way a median-imputing model meets it, and the gaps themselves are scored by the separate *was missing*
suggestion. The signal is diluted into the median bin (MI 0.056 on the reproduction), not erased. Doing what the
review proposed (gaps as their own code) cut the missing flag's gain from +0.022 to +0.005 on the same data, which is
the MIN_GAIN threshold, so it would hide the very feature a median-imputing model needs. The real defect was in bins
(2.2, 2.3).

## Real, won't fix now

**12.5a: bar orientation in the hover ball.** `PointTracker._collect()` calls bars horizontal when more of them start
at x = 0 than at y = 0. Checked against `BarContainer.orientation` on all 7 graph types that draw bars, every choice
and on/off option one at a time, with and without *Colour by*, both orientations: 249 drawings, 0 wrong. It fails
for bars that don't start at 0 (`barh(left=5)`: the hover shows `x: 5 – 8 | y: 0.8`; `bar(bottom=10,
align='edge')` starting at x = 0) and for a single edge-aligned horizontal bar at y = 0 (a tie). No built-in graph
draws those, and the *Python code* tab is read-only.
- A: read `BarContainer.orientation` per bar now, keep the guess as fallback (about 10 lines and a test).
- B: leave it, and do A with the first graph that draws floating bars (waterfall, Gantt, ranges).
- Recommendation: B. Nothing users can reach is wrong today; A is cheap whenever you prefer it.

**12.5b: contour labels over an image on dark paper.** Style *image* with *Contour labels*: on dark paper the black
contour lines turn light grey (`#000000` → `#d4d4da`) but their labels stay black, because texts on an axes with a
colour mesh are left alone (that rule protects heatmap cell numbers). The labels are exactly as readable as on light
paper (same black on the same image); they just no longer match their lines. Style *filled + lines* turns both light.
- A (review): recolour the labels like their lines. On matplotlib 3.8+ the labels can be found through the contour
  set in `ax.collections`; on 3.6–3.7 (supported) nothing links them to their lines, so it needs a guess there.
- B: leave lines and labels drawn over an image or filled contours as they are on both papers: they sit on the data
  colours, not on the paper. This also changes *filled + lines* (its lines and labels would stay black).
- C: leave it as it is.
- Recommendation: B, since only the paper changes and the image under the lines does not. It changes a look that
  works today, so it needs your OK.

**12.4a (rest): fail or drop when the test file lacks a training column.** 3.0.1 keeps dropping and now says which
columns. A: keep that (any submission still works). B: stop with an error listing the columns. C: ask in the dialog
before training. Recommendation: A, with C later if users miss the message.

**T.2: the 500,000-row window test is timing-sensitive.** It fails when one event-loop step takes 1.5 s or more.
In this session it failed in 2 of 11 full runs: 1.57 s (Python 3.12 / pandas 3.0, the first run after the container
restarted) and 1.50 s (Python 3.12 / pandas 2.1), both while applying a step, and it passed on every rerun. It is
not a 3.0.1 regression: replaying the scenario in the same suite context (tests/core, test_design, then this file;
pandas 2.1, two runs each) gave a longest step while applying of 0.64 and 0.77 s at v3.0 and 0.65 and 0.74 s at
3.0.1. So the usual margin is about 2x. The rare spikes look like load on this 2-core machine (the window, the Lab's
worker thread and the test share it), but their cause is not pinned down.
- A: leave it. The limit is the point of the test, and a failure means the window really froze for 1.5 s.
- B: measure the phase again once before failing (no new dependency needed).
- C: raise the limit to 2 s.
- Recommendation: A for now, B if it fails on your machine too.

**12.6 (related): the title step's own code.** `clean.py` still has `title = title.replace({...})`. On pandas 2.2
only, it warns when no value of a file matches the pattern (e.g. a test file whose names are all missing); a normal
test file is quiet. A: leave it (pandas 3 removed the warning; `.replace` is the clearest code to read). B: write
`.map(lambda v: {...}.get(v, v))` in the exported code. Recommendation: A.

## The test that was changed (T.1)

`test_regression_equation_writes_a_minus_sign` now has its own generator, as the review asked, and its data use an
intercept of -3.5 instead of -3. The assertion is unchanged (`"+ -" not in text` and `·x - 3.\d`). With -3, the
fitted intercept sits on the edge of `- 3.x` (any draw that lands above -3 prints `- 2.9…`: 47 of 58 draw orders
did), and the review's local `default_rng(11)` draws print `- 2.92`. With -3.5 the edges are 7 standard errors away
(SE of the intercept ≈ 0.07). After: 0 of 58 draw orders fail.

## What users will notice

- *Suggest* and *Data summary* give the same numbers as the Plot ideas (bias-corrected η and V; ρ for curved links,
  e.g. Titanic `Fare` ρ +0.32 instead of r +0.26).
- The Feature Lab: bins and logs always read *Same information, new shape*; differences of numbers that are often 0
  are suggested; `not` / `and` / `or` in a formula are logical on number columns (true / false; a gap counts as
  false); a formula
  with a line break is refused; a rename to a taken or multi-line name is refused with a message; removing a step
  also removes a target encoding that learns from its column.
- *Evaluate with model*: the linear model one-hot encodes bins and numbers read as groups. Titanic, title +
  family_size: 0.802 → 0.823 (+0.020, not significant), was 0.789 → 0.825 (+0.036).
- Plot ideas: a curved link on log axes is a scatter on log axes, not a scatter with a straight line.
- Loading files: day-first dates read right (also on pandas 1.5); European numbers like 1.234,56 are kept; new
  notes for values that were not dates and for separator-only lines skipped above the header.
- Column names with spaces around them keep their Plot ideas and Column types; *skip* leaves a column out of the
  slots, Suggest, Plot ideas, Feature Lab and Evaluate.
- The plot and the *Python code* tab redraw after Feature Lab changes; Column types survive undo.
- A pie of zeros and correlations of one-value columns explain what is wrong; a Kaggle submission names the columns
  the test file lacks.
- Exported plot scripts and `clean.py` run on their own whatever the data contains or the file is called.
