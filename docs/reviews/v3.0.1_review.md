### 1. Unify Association Metrics & Sample Size Across All Tabs (`plotstudio/recommend.py`)

* **File & Lines**: `plotstudio/recommend.py` (lines 29, 85–112, 127–213)
* **Problem**: `plotstudio/core/assoc.py` (used by **Plot ideas**) computes bias-corrected Cramér's $V$ (Bergsma 2013), bias-corrected rank/raw correlation ratio $\eta$ ($\epsilon^2$), and $\max(|r|, |\rho|)$ on a `50,000`-row sample (`profiler.SAMPLE_ROWS`). However, `plotstudio/recommend.py` (used by **Columns › Suggest**, **Suggest all columns**, and **Data summary › Link to target**) still uses its own uncorrected `eta()`, uncorrected `cramers_v()`, and Pearson-only `corr()` on a `20,000`-row sample (`SAMPLE = 20_000`). High-cardinality noisy categories (e.g., 45 groups in 90 rows) score `V = 0.00` in **Plot ideas** but `V = 0.70` (ranked #1) in **Suggest** and **Data summary**.
* **Required Fix**:
  1. Set `SAMPLE = 50_000` (matching `plotstudio.core.profiler.SAMPLE_ROWS` and `random_state=0` with `.sort_index()`).
  2. Delegate `recommend.eta()` and `recommend.cramers_v()` to `plotstudio.core.assoc`:
     - In `eta(values, groups)`, encode `groups` via `assoc.codes_of(groups)` and call `assoc.eta(codes, len(labels), pd.to_numeric(values, errors="coerce").to_numpy(dtype=float))`.
     - In `cramers_v(a, b)`, encode `a` and `b` via `assoc.codes_of`, build the table with `assoc.crosstab`, and return `assoc.cramers_v(table)`.
  3. In `Profile.link(col)`, when scoring two numeric columns (`self.tkind == "number" and i.kind == NUMERIC`), compute both Pearson $r$ and Spearman $\rho$ (via `assoc.number_matrices` or `assoc.pearson_pair`) and rank by `max(abs(r), abs(rho))`, displaying `ρ` when `abs(rho) > abs(r) + 0.1`.

### 2. Fix False Mutual Information Gain on Binned Features with Missing Values (`plotstudio/core/feature_lab/scoring.py` & `base.py`)

* **Files & Lines**: `plotstudio/core/feature_lab/scoring.py` (lines 70–88) and `plotstudio/core/feature_lab/base.py` (lines 48–63)
* **Problem**:
  - In `scoring.py:codes(s, kind, bins)`, a continuous numeric column (`kind == "number"`, $>15$ unique values) has its missing values filled with the median (`x.fillna(x.median())`) before quantile binning, erasing the missingness signal from `mi_before`.
  - When `Binning` (`binning.py`) bins that column into $k = 4\text{..}10$ bins (`pd.cut(..., labels=False)`), the resulting series has $\le 10$ unique values, so `feature_kind()` classifies it as `"category"`, where `codes()` places `NaN` into its own `"\x00missing"` group.
  - Consequently, whenever missingness is informative about the target, `c_bin` gets an artificial MI gain over its source column and `base.py:58` (`if self.gain > MIN_GAIN: return "recommended"`) overrides `self.neutral = True`, falsely promoting `c_bin` to `"Adds information"` ahead of `missing_flag`.
* **Required Fix**:
  1. In `scoring.py:codes()`, keep missing values as their own separate code (`bins`) for `"number"` columns instead of imputing them into the median bin before computing MI:
     ```python
     if kind == "number":
         x = pd.to_numeric(s, errors="coerce").astype(float).replace([np.inf, -np.inf], np.nan).to_numpy()
         out = np.full(len(x), bins, dtype=np.int64)
         ok = np.isfinite(x)
         if ok.any():
             out[ok] = quantile_codes(x[ok], bins)
         return out
     ```
  2. In `base.py:FeatureSuggestion.status` (line 58), check `if self.neutral: return "neutral"` **before** `if self.gain > MIN_GAIN: return "recommended"` so order-preserving single-column transforms (`log1p`, `bin`) always retain their `"neutral"` (`"Same information, new shape"`) status.

### 3. One-Hot Encode Binned Features and Categorical Numbers in Model Evaluation (`plotstudio/core/evaluate.py`)

* **File & Lines**: `plotstudio/core/evaluate.py` (lines 102–120)
* **Problem**: `binning.py` states that equal-count bins allow a linear model to *"treat low, middle and high values differently,"* and `profiler.py` classifies `c_bin` and discrete numeric columns (such as `Pclass` or user-overridden category columns) as `kind == "category"`. However, `evaluate.py:model_columns()` checks `elif pd.api.types.is_bool_dtype(s) or pd.api.types.is_numeric_dtype(s): nums.append(c)` before checking `kind == "category"`, sending binned features and discrete numeric categories into `StandardScaler` as a single linear term instead of `OneHotEncoder`.
* **Required Fix**:
  - In `evaluate.py:model_columns()`, route columns with `kind == "category"` (that are not binary `0/1` or `bool` and have `2 < s.nunique(dropna=True) <= MAX_GROUPS`) and columns produced by `op == "bin"` into `cats` so `LogisticRegression` / `Ridge` one-hot encodes them:
    ```python
    elif kind == "category" and not pd.api.types.is_bool_dtype(s) and 2 < s.nunique(dropna=True) <= MAX_GROUPS:
        cats.append(c)
    elif pd.api.types.is_bool_dtype(s) or pd.api.types.is_numeric_dtype(s):
        nums.append(c)
    ```

### 4. Prevent Linear Regression Fit on Log-Scaled Axes (`plotstudio/core/plot_recommender.py` & `plotstudio/graphs.py`)

* **Files & Lines**: `plotstudio/core/plot_recommender.py` (lines 727–736, 885–900) and `plotstudio/graphs.py` (lines 1019–1056)
* **Problem**: When two skewed numeric columns have a curved monotonic link ($|\rho| > |r| + 0.1$), `plot_recommender.py` selects `graph="regression"` (`sns.regplot` + linear `np.polyfit(x, y, 1)`) and sets `logx=True` / `logy=True`. Fitting an ordinary straight line $y = mx + b$ in raw space and then applying log axes causes the line to curve wildly, plunge to $-\infty$ wherever $mx + b \le 0$, distort axis limits, and display an unlogged linear equation/R² that contradicts the log axes.
* **Required Fix**:
  - In `plot_recommender.py:d_pair()` (lines 894–898), when `abs(rho) > abs(r) + 0.1` and `self.logs_for(a)` or `self.logs_for(b)` is `True` (and `spec["graph"] == "regression"`), switch `spec["graph"] = "scatter"`, `spec["opts"] = {"alpha": 0.6}`, and `spec["plot"] = "scatter (log)"` so log-scaled relationship recommendations are drawn cleanly without an invalid raw-space linear fit.

### 5. Fix Zero-Inflated Handling in Numeric Pair Generators (`plotstudio/core/feature_lab/generators/numeric_pairs.py`)

* **File & Lines**: `plotstudio/core/feature_lab/generators/numeric_pairs.py` (lines 23–30, 76–83)
* **Problem**:
  - In `oriented(ctx, a, b)`, `za = float((xa == 0).mean())` divides by `len(df)` including `NaN`s, biasing orientation toward columns with more missing values.
  - In `NumericDiff.candidates(ctx, cols)`, `ma = float(np.nanmedian(np.abs(ctx.numeric(a))))` is `0.0` whenever $>50\%$ of non-missing values are `0`, causing `if ma > 0 and mb > 0` to skip zero-inflated columns (such as delays or discounts).
* **Required Fix**:
  - In `oriented()`, compute `za = float((xa.dropna() == 0).mean())` and `zb = float((xb.dropna() == 0).mean())`, and use non-zero values when comparing scale medians (`np.nanmedian(np.abs(xa[xa != 0]))`).
  - In `NumericDiff.candidates()`, compute scale using `float(np.nanmedian(np.abs(x[x != 0])))` (falling back to `np.nanmean(np.abs(x))`) so zero-inflated columns of comparable scale are paired.

### 6. Fix European `DD/MM/YYYY` Date Detection & Missing Coercion Notes (`plotstudio/data.py`)

* **File & Lines**: `plotstudio/data.py` (lines 291–313, 446–453)
* **Problem**: `_try_datetime()` loops `for dayfirst in (False, True):` and returns immediately on the first mode that parses $\ge 90\%$ of rows. On a `DD/MM/YYYY` dataset where $\ge 90\%$ of rows have day $\le 12$ and $\le 10\%$ have day $> 12$, `dayfirst=False` wins—swapping day and month on $\ge 90\%$ of rows and coercing the remaining $\le 10\%$ into `NaT` without recording a note.
* **Required Fix**:
  1. In `_try_datetime()`, evaluate both `dayfirst=False` and `dayfirst=True` on `sample`. If both reach `>= 0.9` and `plausible()`, prefer `dayfirst=True` whenever it parses strictly more non-null values on `sample` (or on `s`).
  2. In `load_csv()` (lines 446–453), compute `bad = int(new.isna().sum() - s.isna().sum())` when converting dates and append `f"'{name}': read as dates; {bad:,} value(s) that were not dates became missing."` to `notes` when `bad > 0`.

### 10. Fix Logical `not`, `and`, `or` on `0/1` Integer and Float Columns (`plotstudio/core/feature_lab/safe_expr.py`)

* **File & Lines**: `plotstudio/core/feature_lab/safe_expr.py` (lines 149–151, 166–172)
* **Problem**: `safe_expr.py` compiles `not x` to `~x` and `a and b` / `a or b` to `a & b` / `a | b`. On a `0/1` integer column (like `Cabin_was_missing` created by `MissingFlag`), `~df['flag']` performs bitwise complement (`-1`, `-2` instead of `1`, `0`). On a float column with `NaN`s (like `is_weekend` created by `DatePart`), `~`, `&`, and `|` raise `TypeError`.
* **Required Fix**:
  - Add a helper method `_bool_code(self, node)` in `_Writer`:
    - If `node` is already an `ast.Compare`, `ast.BoolOp`, `ast.UnaryOp` with `Not`/`Invert`, or an `ast.Call` to `isna`/`notna`, return its written code directly.
    - Otherwise, wrap the operand as `({code}.fillna(0).astype(bool))` so `0/1` integer and float columns work cleanly with `~`, `&`, and `|`.
